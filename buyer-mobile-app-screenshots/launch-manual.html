DALLAS BAKERY WHOLESALE

From this folder to your first paid order.

This manual takes the source code you were handed and turns it into a live store — the website, the payments, the shipping labels, the emails, and then the phone apps. No programming knowledge is assumed. Follow it top to bottom; nothing here is optional except where it says so.

⏱ About half a day, first time 💳 A credit card for accounts 🖥 A Mac or Windows computer

Three words you'll see everywhere

Terminal — a window where you type commands instead of clicking. Mac: open Applications → Utilities → Terminal. Windows: install the free program Git Bash and open that. Every command in this manual is typed there, then you press Return.

Secret — a password-like value you copy from one dashboard and paste into another. Treat every secret like the key to the till: never email it, never screenshot it.

Deploy — one command (npm run deploy) that pushes your latest settings to the live website. Whenever this manual says "deploy again," that's the whole instruction.

Before anything works, install Node.js once: go to nodejs.org, download the version marked LTS, and install it like any app. That's the only program the whole setup needs.
Part 1 ACCOUNTS

Open five accounts

About an hour. Use your business email for all of them, and write each login down somewhere safe.

1

Cloudflare — hosts the website

Sign up at cloudflare.com. The free plan works; the $5/month Workers Paid plan is recommended once you're live. While you're there, click Add a site and follow the steps to bring dallasbakery.net into this account — Cloudflare shows you exactly what to change at your current domain company.

2

Stripe — takes the card payments

Sign up at stripe.com and complete business activation (bank account, tax ID). Free to open; Stripe keeps roughly 2.9% + 30¢ of each card payment and deposits the rest to your bank.

3

Resend — sends your email

Sign up at resend.com. This sends buyers their sign-in codes, order confirmations, and tracking numbers. The free tier easily covers a small bakery.

Without this one, buyers literally cannot sign in — their code arrives by email.

4

UPS developer access — buys shipping labels

Go to developer.ups.com, sign in with your existing UPS account, and create an "app". It gives you a Client ID and Client Secret. You'll also need your six-character UPS account number — it's on any UPS invoice.

5

Expo, Apple & Google — for the phone apps (can wait)

expo.dev (free, builds the apps), developer.apple.com ($99/year — business verification can take a few days, so start it early), and play.google.com/console ($25 once). Skip these until Part 4 if you want the website live first.

Part 2 THE WEBSITE

Put dallasbakery.net live

About two hours. Open Terminal, then copy each command below — the button on each block copies it for you.

1

Go to the website folder and connect to Cloudflare

cd wholesale-site
npm install
npx wrangler login

The last command opens your browser — log into Cloudflare and click Allow.

2

Create the database

npx wrangler d1 create dallas-bakery-wholesale

This prints a database_id — a long string of letters and numbers. Open the file wrangler.deploy.jsonc in any text editor, find REPLACE_WITH_D1_DATABASE_ID, paste your id in its place, and save.

Then load the database's tables (run this again after every future update, too):

npm run db:migrate
3

Set the secrets

For each row of the table, run this command with the NAME filled in, and paste the value when it asks:

npx wrangler secret put NAME --config wrangler.deploy.jsonc

Where the table says random, make one by running openssl rand -base64 32 and copying what it prints.

4

Deploy, then attach your domain

npm run deploy

In the Cloudflare dashboard: Workers & Pages → dallas-bakery-wholesale → Settings → Domains & Routes → Add → Custom domain → type dallasbakery.net.

5

Tell Stripe where to report paid orders

In Stripe: Developers → Webhooks → Add endpoint.

Endpoint URL: https://dallasbakery.net/api/webhooks/stripe
Events to send: tick payment_intent.succeeded and checkout.session.completed.

After saving, Stripe shows a Signing secret (starts whsec_). Store it as STRIPE_WEBHOOK_SECRET using the step-3 command, then deploy again.

This is the messenger that carries every paid order into your shipping queue. Without it, cards get charged but no order ever appears.

6

Verify your email domain

In Resend: Domains → Add domain → dallasbakery.net. Resend lists 3–4 DNS records. In Cloudflare, open your domain → DNS → add each record exactly as shown. Come back to Resend until it says Verified.

Hard blocker: until Resend shows Verified, buyers cannot receive sign-in codes — which means nobody can order.
7

Log into your admin

Go to https://dallasbakery.net/admin. Sign in with sales@dallasbakery.com and the temporary password from step 3 — it will ask you to choose a permanent one. The Launch connections panel shows a checklist of everything above; each row tells you what's still missing.

Part 3 DAY TO DAY

Running the store needs no Terminal

Everything from here on happens by clicking around dallasbakery.net/admin:

Products — add a bread, change its name, description, price per loaf, loaves per case, photo, and the packed box's weight and size. UPS buys each case's label from those exact numbers, so enter what the box really weighs. Hide takes a bread off sale; Delete removes it for good (past orders keep their records either way). Changes appear on the website and app instantly.
Account approvals — new wholesale applications wait here. Approve or decline; approved buyers can order the same minute. On an approved business's card you can also add extra delivery locations for their other stores.
Bake sheet — every morning, how many cases of each bread today's unshipped orders need. There's a Print button sized for the bench.
Shipping queue — tick orders → Create labels → Print labels (your thermal printer) → Mark shipped, which emails every buyer their tracking number automatically. A not-yet-shipped order can be refunded in full from its row.
Case shipping — the per-case shipping price buyers pay, and the fallback box weight.
Part 4 THE PHONE APPS

Put the buyer app in the stores

Do this only after the website works — the apps are a window onto it. Expect 1–3 weeks total, mostly waiting on Apple.

1

Install the build tool

npm install -g eas-cli
eas login
2

Configure the buyer app

cd buyer-mobile-app
npm install
eas build:configure

Then on the expo.dev website, open your project → Environment variables and add two, for the production profile:

EXPO_PUBLIC_API_URL = https://dallasbakery.net
EXPO_PUBLIC_STRIPE_PUBLISHABLE_KEY = your pk_live_… key

The build refuses to finish without these — that's deliberate, because an app without them would install fine and then fail at checkout.

3

Test on a real phone first

eas build --profile preview --platform ios

Install the build it gives you on your own phone and pay for one small order. The card sheet only exists in real builds — no web preview can test it.

4

Build and submit

eas build --platform ios
eas build --platform android
eas submit --platform ios
eas submit --platform android

EAS asks the Apple/Google signing questions — accepting the defaults is fine. In App Store Connect, fill in the listing (the screenshots are included in this package).

Apple needs a demo login. The app is sign-in-only, so approve a test application for an inbox you control, and in the review notes tell Apple: "Sign in with that email — a six-digit code is emailed to it." Reviews take 1–3 days and a first rejection is normal; fix what they name and resubmit.

The owner app (owner-mobile-app) follows the same steps and only needs EXPO_PUBLIC_API_URL.

If something breaks

Buyers don't receive sign-in codesResend domain isn't Verified yet — Part 2, step 6.
Card charged but no order in the adminWebhook secret wrong, or the endpoint URL has a typo — Part 2, step 5.
Labels failUPS credentials wrong, or UPS_ENVIRONMENT still says test.
The card form never loadsSTRIPE_PUBLISHABLE_KEY is missing or is a sk_ key by mistake.
Any secret was wrongFix it with the step-3 command, then npm run deploy again. That pattern fixes almost everything.
